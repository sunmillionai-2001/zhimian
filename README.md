## 快速开始

### 方式一：直接打开（离线题库与本地记录）

双击 `app.html`，或用浏览器打开它即可。**离线题库与浏览器记录无需安装依赖**（字体联网加载，断网回退系统字体）。

### 方式二：启动本地服务（使用 AI 与复盘 API）

```bash
npm ci
node server.js
```

然后打开：**http://127.0.0.1:8123/app.html**

- 端口可用环境变量覆盖：`PORT=9000 node server.js`
- 服务提供：静态托管、结构化 AI（`/api/ai/*`）、面试复盘（`/api/reviews`）、文件文字提取（`/api/resume/import`）；`/api/store` 为未接线的预留接口。

## 第一轮缺陷修复（2026-10-12）

- 静态服务只允许 `/`、`/app.html`、`/index.html`、`/index-sidebar.html` 与公开技能目录 `/skill-learning.js`、账号页 `/account.html` 及账号脚本 `/account-session.js`；账号模式工作台页面需登录且有有效权限。配置、数据、Git、服务端源码均不发布；非法编码、路径穿越、越界符号链接、非法 JSON 和超过 5 MB 请求有明确错误响应。
- 每次开始重新解析当前 JD；支持手动选择岗位方向，专业题按岗位过滤，不足的题量用通用行为题补齐。未识别岗位会提示，当前仍是关键词规则，不是 AI 语义解析。
- 自动保存逐题回答、耗时、当前题号和报告自评；刷新会恢复草稿。保存后可查看完整历史报告，不再限制为最近 8 条。新面试替换草稿前有确认提示。
- 备份导入先校验再合并，同 ID 去重，已有草稿优先保留；旧摘要不伪造回答。保存失败明确提示，当前内存中的回答仍可导出。损坏的存储停止覆盖，可导出原始数据供排查。
- 自动保存只承诺当前浏览器。浏览器清理、隐私模式或存储容量限制可能使写入失败，需关注页面提示并导出备份。

## 首页与面试复盘 API（2026-10-13）

通过 `node server.js` 运行时，首页、复盘列表和分析共用同一份服务端数据：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/reviews` | 返回 `{schemaVersion:1, records:[], summary:{...}}`，首页与复盘同时读取 |
| `POST /api/reviews` | 新增记录；相同 ID 和内容重试不会重复新增，ID 内容冲突返回 409 |
| `DELETE /api/reviews/:id` | 删除记录并返回最新记录和统计；重复删除可安全重试 |
| `POST /api/reviews/import` | 合并旧浏览器记录，记录迁移批次，避免删除后重新导入 |

新增记录字段：`id`、`company`、`role`、`stage`、`result`、`date`、`tags`、`note`；`date` 为有效的 `YYYY-MM-DD`。`stage` 为初面/二面/三面/HR面，`result` 为待定/通过/未通过。

统计口径：累计次数按面试轮次记录计数；通过率 = 通过 /（通过 + 未通过），不含待定；待补强项按不同薄弱点标签计数，同一记录内重复标签去重。最近记录按新增顺序显示。

账号模式数据写入 `data/users/<账号ID>/reviews.json`，使用临时文件加原子替换；异常文件不覆盖为零。接口失败时保留表单，展示错误或只读缓存，并提供重新连接。浏览器旧复盘保留原始键；新记录不再依赖浏览器缓存成功才完成服务端保存。

账号模式下复盘按账号隔离，同一账号在不同浏览器访问同一服务可读取自己的复盘。其他模块尚未自动跨设备同步。模拟面试报告属于训练数据，暂未纳入真实面试通过率；AI 点评与追问已接入模拟面试模块。


## 模拟面试 AI 与简历助手（2026-10-13）

- 面试：作答后主动点「AI 点评并追问」，按切题、结构、事实证据、深度四维给训练建议，引用实际回答；补答一次后再次点评，不无限追问。修改初答会清除旧点评。点评、追问、模型及评价版本一起保存到草稿、报告与备份。
- 简历：粘贴正文（最多 30000 字）与可选 JD，先诊断并逐段提问；补充真实经历、勾选确认后才生成候选。可手动编辑并明确采用；原文保留，每次采用保存完整快照与补充事实。支持文本导出、版本复制及带入下一场模拟面试。已扩展 PDF/Word .docx 导入与改写对比（见下节），不提供云同步。
- 字段与引用校验会拒绝不在原材料中的引用和新增数字；这不能保证每条改写语义完全真实，候选仍需本人核对采用。连接失败或输出异常保留材料和已有结果，可重试。
- 服务端共享传输位于 `ai-service.js`，任务分别为 `POST /api/ai/test`、`/api/ai/interview`、`/api/ai/resume-diagnose`、`/api/ai/resume-rewrite`；等待上限 45 秒，浏览器 50 秒。
- 28 项 Node 回归及浏览器端受控模型与跨模块流程已通过，未配置真实 Key，因此真实供应商输出质量和兼容性尚未验收。

视觉沿用纸色背景、朱砂红按钮与墨色文字。简历桌面页采用左侧材料、右侧诊断，手机叠为单列；新增区域检查了 320/390/820px 无页面横向溢出，保留焦点指示与减少动画偏好。


## 岗位关联、个人答案与文件导入（2026-10-13）

- **岗位进度**：待投递 / 已投递 / 面试中 / 已获 Offer / 已结束；可编辑来源链接、JD 和下次面试时间，按状态筛选。状态由用户维护，不自动推断。详情集中展示已保存训练、当前草稿、真实复盘及个人答案；旧的无关联记录不自动猜测归属。
- **历史关联**：新面试和复盘可选择岗位，保存 `jobId` 与当时公司、岗位、JD 快照。后续修改或删除岗位不会改写历史；岗位仍存当前浏览器，复盘仍通过服务端 API 保存，尚未统一云同步。
- **岗位迁移与备份**：原 `zm_jobs` 保留，迁移到 `zm_jobs_store_v2` 时保留稳定 ID；不确定的旧创建时间不能当作真实投递日期。岗位备份独立导入导出，同 ID 保留现有版本，损坏存储停止覆盖，写入失败保留编辑内容。
- **个人答案**：使用 `zm_answers_store_v1`，最多 1000 个答案、每个最多 100 个版本。保存标题、适用问题、标签、完整答案、可选 STAR 与岗位关联；修改新增版本，旧版可载入编辑再保存。支持搜索、删除、独立备份与去重导入。从 STAR 练习和面试报告带入编辑，需明确点击保存；表单尚未保存的修改不承诺刷新恢复。
- **训练复用**：可将故事带入下一场面试背景，也可在当前题选择故事作为回答（已有内容会提示替换）。历史面试保存回答全文，之后编辑或删除答案不影响旧报告。
- **文件导入**：`POST /api/resume/import` 接收 `{name,base64}`。支持 PDF 和 Word `.docx`，最大 3 MB；PDF 最多 30 页，提取正文最多 30000 字，Word 解压后最多 20 MB。旧 `.doc` 需另存为 `.docx`；图片或扫描版没有文字时提示先 OCR。本版不实现 OCR 或 Word/PDF 版式复刻。
- **预览与确认**：上传只在本机解析进程内处理，不写入业务目录、不发送给模型。预览可编辑、取消或确认采用；确认前正文不变，确认后旧简历归档为版本，保留原有已采用版本。分栏、表格、图形可能改变文字阅读顺序，请核对预览。
- **改写对比**：段落级同时展示原文和可编辑候选，已采用文字单独展示；简历版本可查看原始全文与此版全文，桌面左右对照、手机上下排列。
- **解析依赖**：固定版本 PDF.js 与 Mammoth；文档处理在独立进程运行，设置内存及超时边界。Mammoth 的 CLI 参数依赖通过 override 更新，应用仅调用文字提取 API，不调用 Mammoth CLI。`npm audit` 当前为 0 项已知漏洞。

运行 `npm test` 检查基础、AI 契约及真实 PDF/DOCX 解析；浏览器脚本分别覆盖原有流程、受控 AI 和跨模块关联。所有测试使用虚拟文件及临时目录，不写入真实业务数据。


## 岗位技能差距与模块学习（2026-10-13）

- **仍在「岗位 → 技能地图」内**：从岗位详情带入，或选岗位池 / 粘贴 JD。岗位方向可手动覆盖。当前六类岗位覆盖 AGI、前端、后端、产品、数据分析和算法；未知岗位明确提示，不默认套用 AGI。
- **差距清单**：关键词及别名匹配任职要求，保存 JD 原文片段和必需 / 加分分类；用户可调整类型、移除误匹配、关联已有能力或补充自定义能力。未收录的能力可保存自评，但不伪造课程路径。当前只保存一份目标准备清单；重新分析替换要求，能力与练习记录保留。编辑或删除岗位不会改写已保存分析时的 JD。
- **输入后专注学习**：点击生成清单并成功保存后，先短暂停留，目标输入区再渐隐收起，学习区平滑占满宽度并渐显（视觉过渡约 1.6 秒），随后定位到结果顶部；已有可用计划刷新后保持此展示。通过「调整目标岗位」重新展开填写，岗位要求 / 修正及备份在结果区继续可用。空 JD、保存失败或未知图谱不隐藏输入。
- **能力模块**：24 个模块按待补必需项优先展示，保留基础层级与前置建议。能力逐项记录「未评估 / 待学习 / 学习中 / 能独立实践」和项目依据；Java / Go、Vue / React 等可分别自评。熟练程度由用户确认，不是算法推断或能力认证。

- **练习**：每模块一项实践任务、三条验收标准；保存文字、代码或产出链接及自检结果。无自动代码执行、AI 评分或标准答案认证；自检完成不自动提高能力等级。

## 账号与兑换（2026-10-14）

默认 `npm start` 开启账号模式。访问 `/account.html` 注册或登录（账号 3–40 位字母/数字/下划线/短横线，密码 10–128 位）；新注册账号不能直接使用工作台，需要兑换。管理员不受使用期限限制。

首次先在网页注册自己的账号，再在项目目录将其设置为管理员：

```bash
node account-cli.js admin YOUR_USERNAME
```

刷新账号页即可管理兑换码。后台填写数量、使用天数、批次及可选兑换截止时间。使用期从兑换成功开始；续期接在已有有效期之后。同码同账号重复兑换不会增加期限，其他账号不能再次使用。停用已兑换代码会撤销其贡献的期限，随后续期的截止时间会据此重新计算。完整代码只在生成/下载时提供，后台列表不回传明文。

也可在本机操作（命令生成的代码为真实可用代码，需妥善保存）：

```bash
node account-cli.js issue 10 30 first-batch
node account-cli.js list
node account-cli.js revoke CODE_ID
# 密码遗忘时由管理员协助重置；从环境变量读取，不要写入仓库
node account-cli.js reset-password YOUR_USERNAME
```

重置密码前设置 `ZM_NEW_PASSWORD`，重置会撤销该账号所有现有会话。当前没有邮件验证、短信登录或自助找回密码。

账号、密码派生值、会话摘要、兑换码摘要与操作记录存于忽略的 `data/accounts.sqlite`。兑换通过 SQLite 事务与条件更新完成。Cookie 为 HttpOnly / SameSite=Strict，7 天有效，HTTPS 模式加 Secure；权限和管理员身份在每次服务端请求重新检查。注册、登录和兑换按来源地址限制尝试频次（30 次 / 10 分钟），当前限流适合单实例。

普通账号不能读取或修改旧全局配置，也不能使用通用 `/api/chat` 或旧 `/api/ai/test`；现在可管理和测试自己的模型连接，有效账号可使用工作台 AI 业务接口。当前仅实现工作台整体权限与使用期限，尚未实施 AI 次数扣减、自动支付或自动续费。

复盘与预留 `/api/store` 按登录账号目录保存，客户端不能指定其他账号。简历、模拟面试、技能、岗位和收藏仍在当前浏览器，使用账号专属命名空间；切换账号不会混读原数据。旧无账号浏览器键和旧共享复盘文件保留，不自动归属到新注册账号。需要迁移时可在旧本地模式导出对应模块备份，再登录指定账号导入。`/api/store` 仍未自动接线，账号隔离不等于全模块云同步。

本机兼容模式仅用于原有离线数据及回归：

```bash
ZM_LOCAL_MODE=1 node server.js
```

兼容模式跳过账号校验，只允许 loopback 监听。正式服务默认仍监听 127.0.0.1；部署到反向代理后设置 `PUBLIC_ORIGIN=https://你的域名`，代理需保留 Cookie 并提供 HTTPS。若确需监听其他地址，同时设置 `HOST` 与 `PUBLIC_ORIGIN`。公网部署尚未执行。

验证：`npm test` 包含账号接口回归，`node tests/auth-browser.cjs` 覆盖注册、兑换、账号切换、旧标签页退出、后台生成/停用与手机布局；需已有 Playwright 环境。全部测试使用临时数据库，无售卖数据污染。SQLite 使用 Node 内置模块，运行版本要求保持 Node 22.13+，推荐 Node 24。

## 多模型设置（2026-10-15）

产品仍是「职面·求职面试工作台」，不设站内充值、余额或按次售卖入口。正常使用内置连接由运营方承担模型费用；个人模型为可选项，收费模型的费用由其服务商收取。使用期限仍由兑换码决定，本轮没有变更为永久授权。

### 使用与配置

登录工作台后展开顶部「模型设置」：默认选择「工作台内置 AI」。管理员 `jinchuan` 可展开「管理员 · 内置模型与切换顺序」，编辑预设、保存 Key、测试连接、验证 AI 输出、启用并调整顺序。预设如下，均默认不启用，不预填 Key：

| 预设 | 模型 ID | 默认兼容接口 |
|---|---|---|
| Qwen Flash | `qwen-flash` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| GLM Flash（Z.AI） | `glm-4.7-flash` | `https://api.z.ai/api/paas/v4` |
| DeepSeek Flash | `deepseek-flash` | `https://api.deepseek.com` |

Qwen 也可填写与账号地域匹配的业务空间专属域名。Z.AI 和国内 BigModel 的账号/Key/接口应分别匹配，不认为二者 Key 通用。预设是候选配置，不代表免费额度、生产容量或点评效果的承诺；以服务商当前政策与实际测试为准。

普通用户可展开「添加或管理个人模型」，通过预设或其他兼容接口添加连接，保存/测试后在「当前使用」中选择。支持编辑、留空保留 Key、删除和恢复默认；每账号最多 10 个连接。删除当前连接会恢复内置模式，界面先确认；停用当前连接会提示重新选择，不在后台静默更换厂商。

Key 只在保存时上传；服务端以 AES-256-GCM 加密，列表与编辑表单不回传明文，不放入 localStorage。两个账号不能查看、测试、修改或选择对方连接。旧 `server.config.json` 如有 HTTPS 模型和 Key，首次初始化时迁入「原有内置连接」；以后修改请使用新界面，旧配置文件保留，本地兼容模式继续读取原文件。被删除的预设/旧连接不会在重启后重新生成。

### 执行与恢复

- 内置模式按顺序取最多三条启用且有 Key 的连接。网络、服务商、JSON 或结果契约异常才尝试备用；未确认事实、输入格式错误等用户输入问题不重复调用。
- 所有备用结果仍经过原有事实引用、数字及结构校验，不为兼容模型降低标准。显示并保存本次连接、服务商报告的模型（未报告则为请求模型）、请求模型、切换情况及可用 token 用量；未声称这是供应商账单。
- 个人模式只调用选定连接，失败不转发给内置或其他个人厂商。初答、简历和已保存的结果继续保留。
- 单账号每分钟最多 20 次管理/AI 操作（内置管理有独立共享计数）、最多 2 个模型任务；单进程全局最多 12 个任务。超限提示稍后重试，没有充值解锁。当前限流是单实例内存计数，重启会重置。
- “测试连接”仅 GET `/models` 检查接口、Key 和模型是否可见，响应等待最多 8 秒（另加最多 2 秒 DNS），不触发生成。列表接口不支持或模型未列出时明确报错，可另行“验证 AI 输出”；该操作才执行 JSON 生成，最多等待 15 秒。连接状态与输出验证状态独立保存，修改接口、Key 或模型后清除。个人业务生成响应等待最多 90 秒；内置每条最多 30 秒、最多三条，总预算约 96 秒。另有最多 2 秒 DNS 解析预算；浏览器业务请求等待 105 秒、模型设置等待 12 秒、AI 输出验证等待 20 秒。服务商返回空行保持连接时继续等待完整 JSON；超时会区分尚未连通、已连接但未返回结果、生成结果等待超时。面试/改写最大输出 4096 token，简历诊断和个性化组题 8192；AI 输出验证 64。Qwen/GLM/DeepSeek 预设关闭思考模式，其他兼容接口保持其默认行为。
- 模型接口仅支持公网 HTTPS / 443，不能包含 URL 凭据、查询参数或片段。DNS 每次校验并固定连接地址，拒绝私网、回环、链路本地及特殊 IPv6；不跟随重定向，响应上限 1 MiB。本机 Ollama 和 HTTP 接口不在本轮个人模型范围。

### 保存、接口与验收

连接与选择存于 `data/models.sqlite`，加密主密钥为 `data/model-secret.key`，都已被 Git 忽略。备份/恢复时需配套保留；主密钥丢失时停止读取，不自动覆盖。推荐停止服务后备份整个 `data/`（包括账号与复盘）。

- 用户接口：`GET/POST /api/models`、`POST /api/models/:id`、`DELETE /api/models/:id`、`POST /api/models/:id/test`、`POST /api/models/selection`。
- 管理员接口：对应 `/api/admin/models` 和 `/api/admin/models/:id[/test]`。内置修改权与个人配置权分开，用户请求中的 owner/Key 不会替代服务端选择。
- 原 `POST /api/ai/interview`、`resume-diagnose`、`resume-rewrite` 在账号模式下统一走新路由；本地兼容模式继续走旧单连接，便于旧数据操作和受控回归。

50 项 Node 检查与 6 组浏览器回归通过。新增 `tests/model-contract.cjs` 覆盖密钥隔离/加密/恢复、迁移、内置切换、个人失败不切换、严格校验、并发/频率与 SSRF；`tests/model-browser.cjs` 在隔离服务中注入受控传输，覆盖真实账号接口、设置页面、模型元数据及手机布局。没有使用真实 Key、没有请求真实厂商进行质量验收。

## 模拟面试核心训练（2026-10-15）

在「模拟面试」填写个人简历 / 经历和目标 JD，点击「AI 个性化出题并开始」生成 5 / 8 / 12 道题。可只填其中一种材料；同时填写时题目必须覆盖两种来源，每题的「为什么问这道题」展示逐字原文依据。服务端拒绝虚构引用、重复题目和题量异常；失败保留材料及原草稿，不自动冒充题库生成成功。「题库练习」仍可独立使用。

每题先作答并请求 AI 点评，完成一次针对性追问后可点击「修改后再答一次」。初答、追问和重答分别保存，重答使用同一评价标准独立打分，显示切题、结构、事实证据、深度四项前后变化；分数可能不升反降，不将波动包装为提升。报告保留对比、引用和模型元数据，并汇总已点评 / 重答题数及下一步练习方向。新字段兼容旧 schema v2 草稿与记录；导出、导入和刷新恢复均包含它们，仍保存在当前浏览器。

语音作答使用浏览器 `SpeechRecognition` / `webkitSpeechRecognition`，识别完成的文本追加至回答，核对后自行提交；题目朗读使用 `speechSynthesis`。仅点击语音按钮才请求麦克风，不支持、权限拒绝或语音服务失败时明确提示并保留文字，不声称离线可用或已接自有 ASR。部分浏览器会向其语音服务发送音频，详见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。切题、离开模块、页面隐藏及 AI 提交前停止麦克风；转写结果不自动提交模型。

## 正式模拟与专项练习（2026-10-15）

首页「当前目标与练习」可准备新场次、继续草稿或查看最近正式复盘。模拟面试设置按目标岗位、简历确认、面试官与模式组织：

3. 选择 HR 初面（动机、职责、协作、岗位预期）或业务面试（项目贡献、专业能力、取舍、验证）。角色来自前后端共用 `interview-policy.js`，接口拒绝未知角色，结果保留角色与策略版本。
4. 默认正式模拟：开场介绍＋5 道有原文依据的岗位问题＋候选人反问。预计 15 分钟，倒计时用于节奏提示，时间到不会丢弃回答。岗位问题每题最多两次追问；中途不展示分数和参考答案。追问决策只返回下一步和逐字依据，失败可重试或先进入下一题；可提前结束。
5. 结束后逐项生成统一复盘，仅评价有内容的回答；候选人反问单独保留、不评分。网络或模型失败停止自动调用，已完成部分保留，可继续生成剩余复盘。首页汇总薄弱点，报告可展开查看回答与依据。
6. 点击薄弱问题的「专项重练」先保留正式报告，再新建单题专项草稿，携带当时岗位、简历、面试官及原回答（含追问），直接进入重答对比。原报告不被专项练习覆盖。也可以从设置切换「专项练习」，使用原题库或个性化题逐题点评。
